# Roadmap

С PHASE 4 владелец разрешил автономную работу: каждая фаза — отдельный PR, слияние после зелёного CI. Подробный план и модель данных — в отчёте PHASE 0.

| Фаза  | Содержание                                                                                              | Статус          |
| ----- | ------------------------------------------------------------------------------------------------------- | --------------- |
| 0     | Архитектура и delivery plan                                                                             | одобрена        |
| 1     | Чистый репозиторий и технический фундамент                                                              | принята (PR #1) |
| 2     | Бренд-система и векторный логотип (4 версии), дизайн-система                                            | принята (PR #2) |
| 3     | Авторизация (email и пароль), роли, RBAC, аудит, backup/restore                                         | принята (PR #3) |
| 4     | Core Content Platform: новости, категории, объявления, организации и услуги, события, справочник, поиск | принята (PR #4) |
| 5     | Админ-платформа, CMS, модерация (премодерация, настраиваемый порог)                                     | принята (PR #5) |
| 6     | Кабинет бизнеса, заявки жителей, обращения, опросы, вакансии, «Потеряно и найдено»                      | на ревью        |
| later | VK ID и Telegram Login, worker, объектное хранилище, AI, монетизация, mobile                            | не начата       |

Порядок утверждён владельцем при старте PHASE 3: сначала авторизация, RBAC, аудит и backup/restore, затем контентные модули.
В ТЗ v4 и отчёте PHASE 0 эти фазы шли в обратном порядке (Core Content — PHASE 3, Auth — PHASE 4); ROADMAP — актуальный источник.

## Зафиксированные решения владельца

- Репозиторий: `Kno86/Svetly` (private). `svetly-platform` не создаётся.
- Стек: TypeScript monorepo, Next.js, NestJS (REST), PostgreSQL 18, Prisma 7 (не 8 RC), Docker Compose, Caddy для production.
- Без Redis, MinIO и внешнего поиска на старте. Файлы — через интерфейс хранилища.
- Авторизация MVP: email и пароль. SMS не делаем. VK ID и Telegram — отдельная фаза.
- Модерация: премодерация для новых аккаунтов, порог по умолчанию 3, настраивается в админке.
- Бренд: оригинальный векторный логотип (основной знак с надписью SVETLY, символ приложения, монохромная и инверсная версии). Референс предоставит владелец.
- Среда: Windows с Docker Desktop, `http://localhost:3000`, `docker compose up -d --build`.
