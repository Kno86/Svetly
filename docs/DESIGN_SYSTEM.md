# SVETLY — дизайн-система

> Визуальное направление: A «Рассвет» (утверждено владельцем). Палитра, типографика и правила — `docs/redesign/DESIGN_SYSTEM.md`; здесь — как система устроена в коде.

Витрина всех элементов: <http://localhost:3000/design-system>.

## Архитектурные решения

| Решение          | Выбор                                                                                         | Почему                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Стили            | CSS custom properties + CSS Modules, Tailwind CSS 4 (только theme + utilities, без preflight) | существующие модули работают как раньше; новые экраны собираются утилитами Tailwind на тех же токенах   |
| Источник токенов | `apps/web/design/tokens.ts`                                                                   | значения проверяются тестами (контраст); `app/styles/tokens.css` — зеркало, синхронность проверяет тест |
| Шрифт            | Golos Text (текст) + Literata (заголовки), OFL 1.1, пакеты `@fontsource-variable/*`           | полная кириллица, самостоятельный хостинг: нет запросов к Google и сборка работает офлайн               |
| Логотип          | SVG, сгенерированный скриптом, inline-компонент `<Logo>`                                      | единая геометрия для всех вариантов, без растра и без внешних запросов                                  |
| Компоненты       | собственные в `apps/web/components/ui`, примитивы Radix (`radix-ui`), иконки `lucide-react`   | доступные диалоги, меню и вкладки без самописной логики фокуса                                          |
| Тёмная тема      | `<html data-theme="dark">`, переключатель в шапке, выбор хранится в `localStorage`            | токены переопределены в `tokens.css`; Tailwind-вариант `dark:` работает по тому же атрибуту             |

## Цвета

Базовая палитра взята из ТЗ. Тона для текста и интерактивных элементов добавлены там, где исходный цвет
не проходит WCAG 2.2 AA.

| Токен                              | Значение        | Назначение                                               |
| ---------------------------------- | --------------- | -------------------------------------------------------- |
| `--color-ink`                      | `#24201C`       | заголовки, тёмные поверхности                            |
| `--color-primary`                  | `#B4441E`       | основные кнопки, активные пункты (белый текст 5.55:1)    |
| `--color-primary-soft`             | `#F8E6DD`       | фон активных пунктов                                     |
| `--color-sun`                      | `#F2B441`       | **только декор и акценты**, не цвет текста на светлом    |
| `--color-sky`                      | `#2F5D7C`       | ссылки, фокус, инфо                                      |
| `--color-sage-text`                | `#4E6E4B`       | текст «сообщества» на светлом                            |
| `--color-paper`                    | `#FAF6EF`       | фон страницы                                             |
| `--color-text-primary`             | `#24201C`       | основной текст                                           |
| `--color-text-secondary`           | `#6B6158`       | вторичный текст                                          |
| `--color-border`                   | `#E7DFD2`       | декоративные границы                                     |
| `--color-border-strong`            | `#8C8174`       | границы полей ввода (≥ 3:1)                              |
| `success / warning / error / info` | см. `tokens.ts` | статусы; у каждого есть фон `*-surface`, контраст ≥4.5:1 |
| `focus / focus-on-dark`            | Sky / Sun       | кольцо фокуса на светлом и тёмном фоне                   |
| `overlay`, `surface*`              | см. `tokens.ts` | подложка модальных окон и поверхности                    |

Все пары «текст / фон» из `contrastPairs` проверяются тестом `design/tokens.spec.ts`.

## Типографика, отступы, сетка

- Шкала размеров `xs`–`4xl`. Заголовки адаптивные (`clamp`), основной текст — 16 px, межстрочный интервал 1.55.
- Отступы — шаг 4 px (`--space-1` … `--space-20`).
- Скругления: `sm` 8, `md` 12, `lg` 16, `xl` 24 px, `pill`.
- Контейнер до 76rem (1216 px), поля страницы адаптивные (`--gutter`).
- Сетка: 4 колонки на мобильных, 12 — от 768 px. Утилита `.grid` раскладывает карточки автоматически.
- Брейкпоинты (mobile-first): 480 / 768 / 1024 / 1280 px. Десктопное меню появляется от 1024 px.

## Компоненты (`apps/web/components`)

| Компонент                                                                | Состояния и доступность                                                                      |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| `Button`, `ButtonLink` (primary/secondary/ghost/accent/danger, sm/md/lg) | hover, focus-visible, active, disabled, loading (`aria-busy`), высота от 44 px               |
| `TextField`, `TextArea`, `Select`, `Checkbox`, `Radio`                   | подпись через `label`, подсказка и ошибка через `aria-describedby`, `aria-invalid`, disabled |
| `Card`, `Badge`, `Alert`                                                 | Alert: `role="alert"` только для ошибок, для остальных `role="status"`                       |
| `Skeleton`, `EmptyState`                                                 | состояния загрузки и «пусто»                                                                 |
| `Tabs`, `Breadcrumbs`                                                    | роли ARIA tabs, навигация стрелками, `aria-current`                                          |
| `ConfirmDialog`                                                          | нативный `<dialog>`: фокус удерживается внутри, закрытие по Esc                              |
| `SiteHeader`, `SiteFooter`                                               | ссылка «Перейти к содержанию», мобильное меню с `aria-expanded`, закрытие по Esc             |
| `Logo`                                                                   | `role="img"` с подписью, 4 цветовых варианта                                                 |

Состояния страниц: `app/loading.tsx` (скелетон), `app/error.tsx` (ошибка с кнопкой «Повторить»),
`app/not-found.tsx` (404).

Анимации отключаются при `prefers-reduced-motion: reduce`.

## Разделы, которых ещё нет

Новости, объявления, услуги, организации, события и справочник показаны в навигации неактивными с пометкой
«скоро». Ссылок на страницы-заглушки нет. Когда раздел будет реализован, достаточно поставить
`available: true` в `components/shell/navigation.ts`.

## Чего пока нет (запланировано в фазах, где появятся соответствующие функции)

Date picker, поиск и фильтры, таблицы с сортировкой и пагинацией, dropdown-меню, toast-уведомления, боковая панель
и mobile bottom sheet, индикатор загрузки файлов, тёмная тема.

## Доступность

Ориентир — WCAG 2.2 AA в применимой части. Автоматическая проверка axe-core (правила wcag2a/aa, wcag21aa, wcag22aa)
на главной, на `/design-system` и на странице 404 (desktop 1440 px и mobile 375 px) нарушений не нашла.
Это не полный аудит: проверки со скринридером и ручного аудита не было, о полном соответствии WCAG не заявляем.

## Фотографии

Публичные загруженные фото выводятся через `components/content/MediaImage.tsx` (`next/image`):
оптимизатор Next.js отдаёт AVIF или WebP нужной ширины (`deviceSizes` 390–1920 px) и кэширует их
на год, потому что файлы в `/api/media/:id` неизменяемы. Варианты: `gallery` (4:3, сетка фото),
`cover` (16:9, обложка новости, грузится сразу), `post` (фото в ленте). В `next.config.ts`
разрешён только путь `/api/media/**` без query-строки.

Обычный `<img>` остаётся для вложений в личных сообщениях (оптимизатор запрашивает файл без cookies
зрителя, а такие вложения приватные), для превью только что загруженных фото в формах и в админке.
