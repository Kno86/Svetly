# Личные сообщения и уведомления (PHASE 7b)

## Сообщения

- Только переписка 1:1. На пару пользователей одна беседа (`conversations.pair_key` — уникальный отсортированный `userA:userB`).
- Начать переписку можно только с автором **видимого вам** поста или комментария (`POST /api/conversations` с `postId` или `commentId`). Произвольный ID пользователя API не принимает — это защищает от перебора и рассылок.
- Лимиты: 10 новых бесед за 24 часа, 20 сообщений в минуту, текст до 2000 символов, до 3 фото.
- **Доставка не мгновенная.** Realtime (WebSocket) не реализован. Страница беседы опрашивает `GET /api/conversations/:id/messages?after=<id>` примерно раз в 15 секунд, пока вкладка видима; есть кнопка «Обновить» и отметка времени последней проверки. В интерфейсе это прямо написано.
- Повторная отправка: клиент передаёт `clientId` (8–64 символа `[A-Za-z0-9_-]`). Повтор с тем же ключом возвращает уже созданное сообщение, дубликат не появляется (уникальный индекс `(sender_id, client_id)`). Неотправленные сообщения показываются с кнопками «Повторить» и «Отменить».
- Непрочитанные: `conversation_members.last_read_at` текущего пользователя. `GET /api/me/unread` возвращает количество непрочитанных сообщений и уведомлений; счётчик показывается на кнопке «Кабинет».
- Удаление: только отправитель, мягкое — текст и вложения стираются у обоих, остаётся пометка «Сообщение удалено».
- Пустые беседы (без сообщений) в списке не показываются.

## Доступ (проверяется на сервере)

| Действие                         | Кто может                                     | Иначе     |
| -------------------------------- | --------------------------------------------- | --------- |
| Читать беседу и историю          | только два участника                          | 404       |
| Отправлять                       | участник, если нет блокировки в любую сторону | 404 / 403 |
| Удалить сообщение                | его отправитель                               | 404       |
| Пожаловаться на сообщение        | получатель (не отправитель)                   | 404       |
| Заблокировать                    | собеседник по существующей беседе             | 404       |
| Фото из сообщения (`/api/media`) | владелец файла и участники беседы             | 404       |

Фото для сообщений загружаются через `POST /api/media?scope=private` и помечаются `media_assets.private = true`. Такие файлы нельзя прикрепить к посту, отдаются с `cache-control: private, no-store`. Публичные фото нельзя прикрепить к сообщению.

## Блокировка

`POST/DELETE /api/users/:id/block`, список — `GET /api/me/blocks`. Блокировка запрещает отправку в обе стороны; история остаётся видимой. Заблокированный не получает уведомления о самом факте блокировки — ему показывается «Отправка сообщений недоступна».

## Приватность

- Текст сообщений не пишется ни в журнал аудита, ни в логи приложения. В аудит попадают только действие и ID (`conversation.created`, `message.deleted`, `user.blocked`, `user.unblocked`).
- **Политика модерации:** при жалобе на сообщение сотрудник с правом на жалобы видит текст **только этого сообщения** (до 500 символов), не всю переписку и не фото. Об этом сказано в форме жалобы.
- Сообщения не индексируются (`noindex`), в поиск не попадают.

## Уведомления

Хранятся в `notifications`, видны только владельцу на `/notifications` (`GET /api/me/notifications`, `POST /api/me/notifications/read`). Заголовок — фиксированная фраза по типу события, текст чужих постов и комментариев не копируется.

События: комментарий к вашему посту, ответ на ваш комментарий, решение модератора по посту, комментарию или группе, заявка на вступление в вашу закрытую группу, одобрение заявки. О новых сообщениях отдельных уведомлений нет — их показывает счётчик непрочитанных.

Email и push не отправляются: провайдеры не настроены.

## Ограничения

- Нет групповых бесед, редактирования сообщений, индикатора «печатает» и статуса «прочитано собеседником».
- Нет фонового удаления старых уведомлений.
- Нет realtime-доставки.
