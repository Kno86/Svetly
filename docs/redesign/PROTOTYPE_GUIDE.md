# SVETLY — интерактивный прототип (PHASE C)

Статус: контрольная точка 3. Утверждено направление **A «Рассвет»** + из B: поиск с вкладками и плотные плитки-виджеты для кабинетов и админки (в палитре A). Рабочее приложение (`apps/`, API, база, `main`) не менялось.

## Запуск

```bash
cd docs/redesign/prototype
python3 -m http.server 8090
```

Открыть `http://127.0.0.1:8090/` (стартовая) или сразу `http://127.0.0.1:8090/app/index.html`.

Прототип — статические HTML/CSS/JS без сборки и зависимостей. Нет сети, API, базы, cookie-сессий; роль и режим данных хранятся в `localStorage`/`sessionStorage` браузера.

## Управление (верхняя тёмная панель)

- **Роль:** Гость · Житель · Предприниматель · Администратор. Меняет шапку, доступ к разделам, кнопки действий.
- **Данные:** Есть · Пусто · Загрузка · Ошибка — переключает состояние всех списков.
- **Карта экранов** (`#/screens`) — все маршруты, сгруппированные по зонам, с требуемой ролью.
- Вход: `#/login` → кнопки «Демо-вход» по ролям, или заполнить форму (входит как Житель). Выход — в меню кабинета.

## Демонстрационный сценарий (5 минут)

1. Гость: главная → поиск с вкладками → объявление → «Написать автору» → экран «Войдите».
2. Регистрация: `#/register` → ошибки пустых полей → «Создать аккаунт» → «Проверьте почту» → «Я подтвердил(а)» → выбор интересов.
3. Житель: «Разместить» → объявление → «Отправить на проверку» → «Мои публикации» (статусы, «Снять» с подтверждением) → «Сообщения» → диалог.
4. Предприниматель: переключатель «Житель / Бизнес» → обзор → профиль организации («изменения на проверке») → заявки жителей → ответ.
5. Администратор: «Админка» → очередь → «Отклонить» (причина обязательна) → пользователи → роль → «Заблокировать» (ввод слова) → настройки функций (недоступные заблокированы).
6. Житель открывает `#/admin` → «Нет доступа»; Гость открывает `#/me` → «Войдите» с возвратом.
7. Панель «Данные» → «Пусто» / «Загрузка» / «Ошибка» на любом списке.

## Что реально работает в прототипе

Переходы между всеми экранами · мобильное меню-шторка и нижняя панель · меню админки на mobile · вкладки · фильтры в нижней шторке на mobile · модальные окна и подтверждения опасных действий (Esc, клик по фону, фокус) · валидация обязательных полей, email и длины пароля с сообщениями под полями · переключатели и «нравится»/«пойду» · переключение ролей и проверка доступа · состояния данных · тосты-подтверждения «Демо: …».

## Что только имитируется

Ни одно действие не выполняется: аккаунты не создаются, письма и сообщения не отправляются, данные не меняются, звонков, платежей и административных операций нет. Все имена, организации, события, цены и цифры вымышлены и помечены «пример»; местные телефоны скрыты.

## Только концепция (нет в продукте, помечено «Концепция» в интерфейсе)

Каталог предпринимателей как отдельная вкладка · интерактивная карта · календарь событий и экспорт в календарь · отзывы и рейтинги · публичный профиль пользователя · удаление аккаунта самим пользователем · публикации от имени бизнеса · статистика бизнеса · сотрудники компании · заявки жителей в кабинете бизнеса (сейчас в кабинете жителя) · единая очередь модерации и массовые действия · выбор ответственного за обращение из списка · сравнение «было / стало» в заявках бизнеса · история версий в CMS · полнотекстовый поиск по аудиту · возврат на исходную страницу после входа · шаг выбора интересов при регистрации.

## Известные ограничения

- Прототип проверен автоматически в Chromium; Safari/Firefox и реальные телефоны не проверялись. Скринридером не проверялся.
- Фото — цветные заглушки; логотип в SVG набран шрифтом (кривые — при внедрении).
- Юридические тексты, контакт поддержки и правила — не написаны (решение владельца).
- Это не код продукта: при внедрении компоненты переписываются в `apps/web` по `DESIGN_SYSTEM.md`, а концепции требуют отдельного API.
