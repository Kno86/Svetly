# Интеграции, AI, монетизация и feature flags (PHASE 11)

Ключей, провайдеров и согласованных бюджетов нет. Поэтому фаза даёт только архитектуру и честные статусы «не настроено». Ответов AI и платежей, которые выглядели бы настоящими, платформа не выдаёт.

## Feature flags (ТЗ §19)

- Реестр флагов — `apps/api/src/integrations/features.ts`. У каждого флага указаны ответственный, описание, значение по умолчанию, среды и зависимости.
- Решение администратора хранится в `settings` под ключом `features.overrides`. Каждое изменение записывается в журнал аудита (`feature.updated`).
- Права: `settings.manage`. Раздел админки — `/admin/integrations`.
- Сервер проверяет флаг через `@Feature(key)`: выключенный модуль отвечает `404 FEATURE_DISABLED`. Из меню он тоже пропадает (`GET /api/features`), но скрытие в интерфейсе защитой не считается.
- Средства защиты не управляются флагами: вход, RBAC, CSRF, лимиты попыток, модерация.

| Флаг                 | Статус         | По умолчанию | Сервер                                           |
| -------------------- | -------------- | ------------ | ------------------------------------------------ |
| `recommendations`    | реализовано    | вкл.         | `/api/me/recommendations` и интересы             |
| `groups`             | реализовано    | вкл.         | группы, лента, комментарии                       |
| `chats`              | реализовано    | вкл.         | личные сообщения                                 |
| `ai_assistant`       | не настроено   | выкл.        | `POST /api/assistant/ask` → 503 `NOT_CONFIGURED` |
| `payments`           | не настроено   | выкл.        | —                                                |
| `push_notifications` | не настроено   | выкл.        | —                                                |
| `marketplace`        | не реализовано | выкл.        | зависит от `payments`                            |
| `business_premium`   | не реализовано | выкл.        | зависит от `payments`                            |
| `advertising`        | не реализовано | выкл.        | —                                                |
| `multi_territory`    | не реализовано | выкл.        | PHASE 12                                         |
| `mobile_features`    | не реализовано | выкл.        | доступна только PWA                              |

Включить флаг со статусом не «реализовано» нельзя: `409 NOT_CONFIGURED`.

## AI-помощник (ТЗ §17)

Готовы только защитные функции (`ai-safety.ts`), их проверяют unit-тесты:

- `redactPersonalData` убирает email и телефоны до отправки текста внешнему провайдеру;
- `quoteUntrusted` помещает найденный контент в блок-цитату, из которого нельзя выйти. Так инструкции внутри текста не исполняются как команды (prompt injection).

Чтобы подключить AI, владелец должен согласовать:

- провайдера и договор, политику передачи данных, лимиты стоимости и квоты;
- timeout и retry, логи без чувствительных данных.

Отвечать помощник должен только по опубликованным данным, со ссылками на источники и с подтверждением перед любым действием.

## Монетизация и billing (ТЗ §18)

Таблиц тарифов, подписок и транзакций нет. Они появятся вместе с выбранным провайдером, чтобы не держать неиспользуемую схему. При внедрении нужны:

- планы, подписки, счета и транзакции;
- серверные webhooks с idempotency и сверка статусов;
- возвраты и журнал;
- тесты отказа, повторного webhook, отмены, возврата и расхождения статусов.

Данные банковских карт платформа не хранит. Платёж считается успешным только после подтверждения провайдером на сервере. Реальные платежи и тарифы требуют согласования владельца.
