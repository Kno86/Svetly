# Аналитика и центр уведомлений (PHASE 8b)

## Принципы

- Не храним IP-адрес, user agent, cookies-идентификаторы посетителя и исходный id пользователя.
- Для вошедших пользователей хранится `actor` — псевдонимный хэш (SHA-256 от id, 16 символов). Это **псевдонимизация, а не анонимизация**: при доступе к базе пользователей хэш можно сопоставить. Поэтому доступ к аналитике есть только у ролей с правом `analytics.read` (super_admin, admin), а API отдаёт только агрегаты.
- Браузер ничего не отправляет при включённых Do Not Track или Global Privacy Control.
- Путь страницы хранится без query-строки и фрагмента (токены сброса пароля, фильтры и т. п. не сохраняются).
- Поисковый запрос сохраняется только нормализованным (нижний регистр, до 100 символов) и только если в нём нет email, URL и последовательности из 5+ цифр (телефоны, номера документов); иначе `query = NULL`, сохраняется только число результатов.
- В отчётах скрыты группы меньше 2 событий (`MIN_GROUP`).
- Клик по телефону/сайту — это `contact_click`, а не звонок, покупка или успешное обращение.

## Схема событий (`analytics_events`)

| Событие                 | Откуда                                                         | Поля                                          |
| ----------------------- | -------------------------------------------------------------- | --------------------------------------------- |
| `page_view`             | браузер (`POST /api/analytics/events`)                         | path, module, referrer_host, utm_\*, actor    |
| `contact_click`         | браузер: ссылки `tel:`, `mailto:`, внешние сайты и карты       | path, module, meta.kind                       |
| `client_error`          | браузер (зарезервировано)                                      | path, meta.code                               |
| `search`                | сервер, первая страница `/api/search`                          | module (тип или `all`), query, results        |
| `registration`          | сервер, из журнала аудита `auth.sign_up`                       | actor                                         |
| `publication_submitted` | сервер: объявление, вакансия, находка, пост, обращение, группа | entity_type, actor                            |
| `publication_moderated` | сервер: `moderation.*_approved/rejected/unpublished`           | entity_type, meta.decision, actor (модератор) |
| `comment_created`       | сервер                                                         | actor                                         |
| `conversation_started`  | сервер (без содержимого)                                       | actor                                         |
| `favorite_added`        | сервер                                                         | entity_type, actor                            |
| `event_registration`    | сервер                                                         | entity_id (событие), actor                    |
| `business_application`  | сервер                                                         | actor                                         |
| `business_inquiry`      | сервер                                                         | actor                                         |

Браузер может отправить только `page_view`, `contact_click`, `client_error`. Ограничение — 120 событий в минуту на IP, счётчик в памяти процесса API (при нескольких экземплярах API лимит действует на каждый отдельно). Клиентские события можно подделать, поэтому просмотры и клики — оценка, а не точный учёт; серверные события надёжны.

## Метрики (`GET /api/admin/analytics?days=1..90`, страница `/admin/analytics`)

Часовой пояс всех суточных границ — `Asia/Novosibirsk`.

- **DAU** = число различных `actor` с любым событием за текущие сутки.
- **WAU** = различные `actor` за последние 7×24 ч; **MAU** — за 30×24 ч. Считаются только вошедшие пользователи: анонимные визиты не идентифицируются и в DAU/WAU/MAU не входят.
- **События за период** = `count(*)` по `name` за `days` суток.
- **Разделы** = `page_view` по первому сегменту пути.
- **Источники** = `utm_source` (или домен-реферер) и `utm_medium` для `page_view`.
- **Частые запросы / без результатов** = сохранённые запросы (`results = 0` для второго списка).

Retention, конверсии сценариев и популярность категорий будут посчитаны, когда накопятся реальные данные. Нулевые значения показываются как есть.

## Хранение

Срок хранения — настройка `analytics.retentionDays` (по умолчанию 180, от 30 до 730), меняется через `PATCH /api/admin/settings` `{ "analyticsRetentionDays": N }` с записью в журнал аудита. Старые события удаляются при каждом открытии отчёта (`AnalyticsService.purge`). Фонового планировщика нет.

## Центр уведомлений

- Категории: модерация, комментарии и ответы, группы, обращения, бизнес, системные. Обязательные (нельзя отключить): модерация, обращения, бизнес, системные. Отключаемые: комментарии, группы. Настройки — `GET/PUT /api/me/notification-settings`.
- Новые типы: решения модератора по объявлениям, вакансиям и находкам; смена статуса обращения; новая заявка организации; итог проверки карточки бизнеса.
- `GET /api/me/notifications?category=&unread=1` — фильтр; в ответе `unread` по категориям. `POST /api/me/notifications/read` принимает `ids` или `category`.
- Защита от дублей: уникальный индекс `(user_id, dedupe_key)` и `createMany({ skipDuplicates })`. Ключ задаётся там, где повтор реален (заявка организации, смена статуса обращения).
- Заголовки — фиксированные строки, без текста чужих сообщений и комментариев.
- Внешние каналы (email, Telegram, web push) не подключены: нет согласованных провайдеров и ключей. API честно отдаёт `channels: { inApp: true, email: false, push: false, telegram: false }`.
