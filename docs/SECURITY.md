# Безопасность

## Секреты

- Секреты хранятся только в окружении (`.env`, `.env.production` или секреты CI/хостинга). `.env*` в `.gitignore`, исключение — `.env.example` без секретов.
- В таблице `settings` хранятся только несекретные настройки.
- Значение `svetly_local_dev_only` в `.env.example` и `compose.yaml` предназначено только для локальной разработки. В режиме `SVETLY_ENV=production` API не стартует, если строка подключения содержит `local_dev_only`.
- Логи API (pino) маскируют `authorization`, `cookie` и `set-cookie`.

## Сеть

- Локально на хост публикуется только web:3000. API и PostgreSQL доступны лишь во внутренней Docker-сети.
- В production HTTPS терминирует Caddy (HSTS). Наружу открыты только 80 и 443.
- Web отдаёт `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `X-Frame-Options: DENY`. До запуска публичной части запрещена индексация (`robots.txt` и meta robots).
- Контейнеры api и web работают от непривилегированного пользователя `node`.

## Авторизация (план; реализация — в фазе Auth)

Решения владельца: в MVP вход по email и паролю. SMS не делаем. VK ID и Telegram Login — отдельная последующая фаза.

- Пароли: хэш Argon2id, минимальная длина 10, проверка по списку распространённых паролей.
- Сессии: непрозрачный токен в cookie `HttpOnly; Secure; SameSite=Lax`, в БД хранится только хэш. Сессию можно отозвать, при смене пароля отзываются все сессии.
- Rate limiting на вход, регистрацию и запрос сброса пароля (по IP и аккаунту), временная блокировка после серии неудачных попыток.
- RBAC проверяется на сервере для каждой операции. Действия администраторов записываются в журнал аудита.

### Подтверждение email и восстановление пароля

- Токены: криптографически случайные, одноразовые, с ограниченным сроком (подтверждение email — 24 ч, сброс пароля — 1 ч). В БД хранится только хэш токена.
- Ответ на запрос сброса одинаков независимо от того, существует ли email, поэтому перечислить аккаунты нельзя.
- Отправка писем идёт через интерфейс `Mailer` с драйверами:
  - `log` (локально, по умолчанию): письмо со ссылкой пишется в лог API. Внешняя почта и платные ключи не нужны.
  - `smtp` (production): SMTP-провайдер задаётся переменными окружения. Выбор провайдера — решение владельца.
- В production драйвер `log` запрещён: API не стартует без настроенного SMTP, если включены email-процессы.
- Неподтверждённый аккаунт не может публиковать контент.

## Модерация (план)

Решения владельца:

- для новых аккаунтов действует премодерация публичных публикаций;
- порог перехода к упрощённой модерации настраивается в админке; по умолчанию — 3 одобренные публикации без нарушений;
- для комментариев и личных сообщений — отдельные механизмы rate limiting, жалоб и модерации;
- ограничения применяются по описанным правилам, у каждого решения есть причина, его можно пересмотреть через админку, оно записывается в журнал аудита. Массовой блокировки контента без правил нет.
