# Места, рекомендации и PWA (PHASE 9)

## Места (`/map`, `GET /api/map`)

- Провайдер интерактивной карты не выбран (нужно проверить условия и цену Яндекс Карт / 2ГИС / MapLibre + тайлы), поэтому `/map` — список мест: опубликованные организации и услуги с адресом и предстоящие события. API отдаёт `provider: null`.
- Ссылка «Найти адрес на Яндекс Картах» — обычный поиск по тексту адреса, без ключа и без встраивания скриптов.
- Координаты необязательны: `latitude`/`longitude` у организаций и событий вводит редакция в CMS и только проверенные. API принимает их только парой и только внутри границ Новосибирской области (`REGION_BOUNDS`), в БД есть CHECK-ограничение. Координаты никогда не вычисляются и не подставляются автоматически.
- Когда провайдер будет согласован: ключ хранится на сервере или ограничивается доменом, карта показывает только записи с координатами, список остаётся запасным вариантом.

## Рекомендации (`/account/recommendations`)

- Только для вошедших. Источники — опубликованные новости и объявления за 30 дней и события на ближайшие 30 дней.
- Правила (`apps/api/src/content/recommendations.ts`): категория из интересов +3; публикация не старше 3 дней +2, не старше 14 дней +1; событие в ближайшие 7 дней +2, в ближайший месяц +1. Записи с 0 баллов не показываются. Каждый балл сопровождается причиной, которую видит пользователь.
- Интересы выбирает сам пользователь (`GET/PUT /api/me/interests`), история просмотров и аналитика не используются. Скрытие — `POST /api/me/recommendations/hidden`, восстановление всех — `DELETE`.
- Территория пока одна, поэтому как фактор не учитывается; добавится с поддержкой нескольких территорий. ML не используется.

## PWA

- `app/manifest.ts` (иконки 192/512/maskable), service worker `/sw.js` (генерируется маршрутом `app/sw.js/route.ts`, `Cache-Control: no-store`).
- Версия кеша = `.next/BUILD_ID`: каждая сборка получает новый кеш, старые удаляются при `activate`.
- Кешируются только статические ассеты (`/_next/static/`, `/brand/`, иконки) и страница `/offline`. HTML-страницы, `/api/*`, кабинет, админка, сообщения и любые URL с query-строкой не кешируются; навигация всегда идёт в сеть, без сети показывается `/offline`.
- Обновление: новый worker ждёт; пользователь видит «Доступна новая версия SVETLY — Обновить», после нажатия worker активируется и страница перезагружается. Проверка обновления — при возврате на вкладку.
- При выходе из аккаунта все кеши удаляются (`clearOfflineData`).
- Регистрация worker только в production-сборке. Push-уведомления не подключены (нет провайдера). В production нужен HTTPS (Caddy).
