# Разделы для жителей и кабинет бизнеса (PHASE 6)

Все правила доступа проверяются на сервере (`apps/api/src/content/*.controller.ts`). Скрытие кнопок в интерфейсе — только удобство.

## Вакансии `/jobs` и «Потеряно и найдено» `/lost-found`

| Действие          | Кто                    | API                                                                                |
| ----------------- | ---------------------- | ---------------------------------------------------------------------------------- |
| Список, карточка  | все                    | `GET /api/jobs`, `GET /api/jobs/:slug`, `GET /api/lost-found?kind=&subject=`       |
| Создать, изменить | вошедший житель        | `POST /api/jobs`, `PATCH /api/jobs/:id` (только свои)                              |
| Снять / «Нашлось» | автор                  | `POST /api/jobs/:id/close`, `POST /api/lost-found/:id/resolve`                     |
| Мои публикации    | автор                  | `GET /api/me/jobs`, `GET /api/me/lost-found`                                       |
| Модерация         | `moderation.community` | `GET /api/moderation/{jobs,lost-found}`, `POST .../:id/{approve,reject,unpublish}` |

- Премодерация: публикации новых авторов ждут модератора. Порог доверия общий для объявлений, вакансий и находок (настройка `trustedThreshold`). Любое отклонение снимает доверие.
- Отклонение и снятие требуют причину, её видит автор.
- Срок: вакансии 7–60 дней (по умолчанию 30), находки 60 дней. После `expiresAt` запись исчезает из публичных списков, карточек, жалоб («автоархив»). Автор продолжает видеть её в кабинете.
- Телефон отдаётся только в публичной карточке, не в списках. `authorId` и заметка модератора публично не отдаются.
- В форме находок есть предупреждение не публиковать номера документов и точные адреса.

## Обращения `/issues`

- Создаёт вошедший житель: категория, суть, описание, место (необязательно), до 6 фото (только свои), контакт (необязательно), согласие на публикацию (`isPublic`, по умолчанию **выключено**).
- Номер — последовательный `number`. Статусы: принято → на проверке → назначен ответственный → в работе → решено / закрыто / отклонено. Отклонение требует объяснения.
- **Кто получает:** только сотрудники SVETLY с правом `issues.manage`. Автоматической передачи в администрацию или другие органы нет — это сказано на странице и в форме.
- Публичный список и карточка — только для `isPublic = true` и не отклонённых. Публично нет автора, контакта, приоритета, ответственного и внутренних заметок.
- История `issue_updates`: смена статуса видна жителю; приоритет, назначение и заметки — внутренние. Публичный ответ платформы требует `issues.respond` (super_admin, admin).
- Ответственным можно назначить только пользователя с ролью сотрудника.
- Лимит: 10 открытых обращений на жителя.

## Опросы `/polls`

- Создают `polls.manage` (super_admin, admin, editor) в `/admin/polls`: вопрос, 2–10 вариантов, даты, режим, разрешение переголосовать. Новый опрос — черновик.
- Один ответ на аккаунт гарантирует уникальный индекс `(poll_id, user_id)`; повтор без `allowRevote` → 409.
- Результаты публичны после закрытия; проголосовавший видит их сразу после ответа.
- Анонимный режим: имена недоступны никому через API. Именной: имена видит только `polls.manage`.
- После первого ответа нельзя менять варианты, режим, правило переголосования и дату открытия.
- На страницах указано, что опрос — не официальное голосование.

## Ограничения

- Уведомлений по email о смене статуса нет: статусы видны в кабинете (`/account/community`). Центр уведомлений — PHASE 8.
- Архивирование логическое (по `expiresAt`), фонового процесса нет.
- Нет карты для места проблемы (PHASE 9) и выбора ответственного из списка в интерфейсе (только API).
