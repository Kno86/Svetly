# Поиск и SEO (PHASE 8a)

## Глобальный поиск

`GET /api/search?q=&type=&category=&sort=relevance|date&page=&limit=` — один запрос к PostgreSQL (`UNION ALL` по модулям), без внешнего поискового движка.

- Морфология: `websearch_to_tsquery('russian', …)` по сгенерированным столбцам `search` (GIN). Опечатки в заголовках — триграммы `pg_trgm` (`similarity`, `%`) и `ILIKE`. Синонимов нет.
- Модули: новости, объявления, организации, услуги, события, справочник, вакансии, «Потеряно и найдено», группы, посты.
- **Только публичное:** опубликованные и не истёкшие записи; группы — только `active` (название и описание закрытых групп и так публичны в каталоге); посты — только из общей ленты и открытых активных групп. Посты закрытых групп, черновики, записи на проверке, обращения, сообщения и личные данные в поиск не попадают. Это проверяет интеграционный тест.
- Фильтр `category` (slug) применяется к модулям с категориями (новости, объявления, организации, услуги, события, справочник); остальные модули при этом исключаются.
- Пагинация: `page` (до 50) и `limit` (до 50), в ответе `total`.
- Подсказки: `GET /api/search/suggest?q=` — до 8 заголовков по тем же правилам видимости (без постов). На странице `/search` выводятся через `<datalist>` после паузы 250 мс.
- История запросов не хранится.

**Ограничения:** нет фильтра по территории — в данных нет структурированной территории, только свободный текст (`area`); появится вместе с multi-territory. Нет исправления опечаток в тексте (только в заголовках) и синонимов.

## SEO

- Индексация выключена, пока не задано `SVETLY_INDEXING=enabled` (в `.env`). `robots.txt` (`app/robots.ts`) читает переменную при каждом запросе; meta robots в layout берёт её значение на момент сборки, поэтому после включения нужно пересобрать web: `docker compose up -d --build`.
- При включённой индексации `robots.txt` запрещает приватные разделы и указывает `sitemap.xml`.
- `GET /sitemap.xml` строится из `GET /api/sitemap`: только опубликованные, не истёкшие записи и открытые активные группы (до 5000 на модуль). Адреса строятся от `SVETLY_PUBLIC_URL`.
- Open Graph: общий образ `/brand/og-image.png` в layout; у карточек новостей, объявлений, организаций и услуг, событий, вакансий, находок и опросов — собственные `title`/`description`.
