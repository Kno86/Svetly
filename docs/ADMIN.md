# Админ-платформа (PHASE 5)

`/admin` — единый интерфейс для сотрудников. Разделы видны по правам роли, но интерфейс ничего не решает сам: каждое действие проверяет API (`@RequirePermission`), и каждое изменение пишется в журнал аудита.

| Раздел                                                                 | Путь                                                   | Право                                                                | API                                               |
| ---------------------------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------- |
| Обзор (счётчики)                                                       | `/admin`                                               | любое staff-право                                                    | `GET /api/admin/dashboard`                        |
| Очередь модерации (все разделы, массовые решения)                      | `/admin/moderation`                                    | `moderation.announcements` и/или `moderation.community`              | `GET /api/moderation/queue`                       |
| Модерация объявлений                                                   | `/admin/moderation/announcements`                      | `moderation.announcements`                                           | `/api/moderation/announcements`                   |
| Жалобы                                                                 | `/admin/complaints`                                    | `complaints.manage`                                                  | `GET /api/admin/complaints`, `POST …/:id/resolve` |
| Новости, события, организации, справочник (CMS)                        | `/admin/content/{news,events,organizations,directory}` | `content.*.manage`                                                   | `/api/staff/*`                                    |
| Проверка организаций                                                   | кнопка в CMS организаций                               | `organizations.verify`                                               | `POST /api/admin/organizations/:id/verification`  |
| Категории                                                              | `/admin/categories`                                    | `content.categories.manage`                                          | `/api/admin/categories`                           |
| Пользователи и роли                                                    | `/admin/users`                                         | `users.read`, `roles.assign`, `users.block`, `users.sessions.revoke` | `/api/admin/users*`                               |
| Журнал аудита (поиск по действию, объекту, автору, результату и датам) | `/admin/audit`                                         | `audit.read`                                                         | `GET /api/admin/audit-log`                        |
| Настройки (порог доверия)                                              | `/admin/settings`                                      | `settings.manage`                                                    | `GET/PATCH /api/admin/settings`                   |

## Жалобы

- Пожаловаться может любой вошедший житель, только на опубликованные объявления, новости, события и организации (`POST /api/complaints`).
- Повторная жалоба на тот же объект, пока первая открыта, не создаёт дубликат (уникальный частичный индекс). Не больше 20 открытых жалоб на одного жителя.
- Жалоба не скрывает публикацию автоматически: решение принимает сотрудник. Закрыть жалобу можно только с комментарием (это проверяет ограничение в БД).
- Причины: спам, мошенничество, оскорбления, неверная информация, другое.

## Проверка организаций

Отметка «Данные проверены» ставится только правом `organizations.verify` (admin и выше) с указанием способа проверки. Дата проверки фиксируется автоматически. Редактор карточки сам поставить отметку не может.

## Порог доверия

`moderation.trustedThreshold` (по умолчанию 3) — сколько одобренных объявлений без отклонений нужно автору, чтобы публиковать без проверки. 0 отключает премодерацию. Изменение действует сразу и пишется в аудит с прежним и новым значением.

## Известные ограничения

- Модерация комментариев и сообщений появится вместе с этими модулями (PHASE 7).
- Нет массовых действий, библиотеки медиа и истории версий материалов.
- Причины модерации вводятся через диалог браузера (`prompt`).
- Аудит фильтруется по точному имени действия; полнотекстового поиска нет.
