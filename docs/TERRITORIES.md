# Территории и мобильные приложения (PHASE 12)

## Что сделано

- Таблица `territories` хранит иерархию «регион → район → населённый пункт» (`kind`: `region` / `district` / `locality`).
- Миграция `20261026090000_territories` создаёт одну цепочку из исходного задания: Новосибирская область → Мошковский район → посёлок Октябрьский и жилой район Светлый. Активна и выбрана по умолчанию только эта территория.
- Защиту обеспечивает база:
  - территория по умолчанию одна (уникальный частичный индекс);
  - неактивную территорию нельзя сделать территорией по умолчанию (CHECK);
  - родителя нельзя удалить, пока у него есть дочерние территории (`ON DELETE RESTRICT`).
- API:
  - `GET /api/territories` — текущая территория и список доступных. В список попадают только активные населённые пункты.
  - `GET /api/admin/territories` — полный список, нужно право `settings.manage`.
- Создавать территории через API нельзя: по ТЗ новая территория появляется только через миграцию по согласованному плану.

## Чего нет и почему

Сейчас территория одна, поэтому весь контент относится к ней. Поле `territory_id` в таблицы контента пока не добавлено. Флаг `multi_territory` остаётся «не реализовано» — это сознательное решение. ТЗ требует не создавать то, что нельзя надёжно проверить, и не менять географию публичных данных без согласованного плана.

## План подключения второй территории

1. Владелец утверждает территорию, модераторов и правила.
2. Миграция добавляет `territory_id` (NOT NULL, FK на `territories`) в региональные таблицы и заполняет его текущей территорией. Региональные таблицы: новости, объявления, организации, услуги, события, справочник, вакансии, находки, обращения, опросы, группы, посты.
3. Общими для всех территорий остаются категории, роли и настройки.
4. Публичные запросы фильтруются на сервере по выбранной территории. Выбрать можно только активную: неизвестный `slug` даёт 404.
5. Роли сотрудников ограничиваются территорией (`user_roles.territory_id`). Модератор одной территории не видит очередь другой.
6. Поиск, sitemap, рекомендации и аналитика получают фильтр по территории.
7. Интеграционные тесты проверяют изоляцию: запись территории A не видна и не изменяется из территории B.

## Android и iOS

Сейчас есть только PWA (PHASE 9): установка, офлайн-страница, обновление. Для работы в production нужен HTTPS.

Нативные сборки не создавались. APK, AAB и IPA в проекте нет. Если владелец решит делать приложения:

- **Android:** обёртка PWA через Trusted Web Activity (Bubblewrap). APK — для тестирования, AAB — для Google Play. Нужны HTTPS-домен, `assetlinks.json` и аккаунт разработчика Google Play.
- **iOS:** нужны macOS, Xcode, Apple Developer Program и отдельная проверка политики App Store для обёрток сайтов.
- **Для обеих платформ:** deep links, единый аккаунт, push через FCM/APNs, политика конфиденциальности.

Решение о стоимости и пользе принимает владелец. До него флаг `mobile_features` выключен.
